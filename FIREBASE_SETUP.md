# Подключение Firebase — по шагам

Проект Firebase «Vocabulary with Ralina» уже создан. Используйте его. Приложению нужен обычный **firebaseConfig веб-приложения**, а не пароль и не ключ администратора.

## 1. Где найти firebaseConfig

1. Откройте [Firebase Console](https://console.firebase.google.com/) и свой проект.
2. Нажмите шестерёнку → **Project settings → General**.
3. В блоке **Your apps** выберите веб-приложение. Если его нет, нажмите значок `</>` и зарегистрируйте приложение.
4. В разделе настройки SDK выберите **Config**. Появится объект `firebaseConfig`.

## 2. Куда вставить

Откройте файл `src/firebase.js`. В объекте `firebaseConfig` замените значения четырёх полей своими значениями в кавычках:

```js
export const firebaseConfig = {
  apiKey: 'ВАШ apiKey',
  authDomain: 'ВАШ authDomain',
  projectId: 'ВАШ projectId',
  appId: 'ВАШ appId',
};
```

Не оставляйте текст «ВАШ». Вставьте реальные значения из Console. Можно вместо изменения файла скопировать `.env.example` в `.env.local` и заполнить эти же четыре значения. Перезапустите `npm run dev`. Не вставляйте service-account JSON, private_key или пароль учителя. Название проекта и его `projectId` могут отличаться.

## 3. Проверьте UID и подготовьте правила Firestore

Текущая версия рассчитана на одного владельца. В **Authentication → Users** откройте свой аккаунт преподавателя и найдите **User UID**. В начале `firestore.rules` функция `ownerUid()` должна возвращать именно этот UID. Это не email, не `projectId` и не API key. Если аккаунт ещё не создан, сначала выполните шаг 4. При значении `__OWNER_UID_NOT_CONFIGURED__` запись закрыта для всех.

Права привязаны к UID, поэтому другие вошедшие аккаунты не получают ни доступа к вашей библиотеке, ни права создавать собственную. Неиспользуемые коллекции, включая `users`, закрыты. Смена email не меняет разрешения; удаление и повторное создание аккаунта меняет UID и требует отдельной настройки.

**Локальное изменение файла не публикует правила. Публикуйте их только отдельным осознанным действием после проверки UID и тестов эмулятора.**

Самый простой способ без команд:

1. В Console откройте **Build → Firestore Database → Rules**.
2. Скопируйте **весь** текст из файла `firestore.rules` проекта.
3. Замените им текущие правила и нажмите **Publish**.

База уже создана в `eur3`, создавать новую не нужно. Коллекции появятся при первом сохранении. Правила закрывают личные наборы и папки от всех, кроме владельца с указанным UID. Ученику доступно чтение только одной публичной копии по её ID, без перечисления других наборов. При чтении проверяется, что набор всё ещё опубликован владельцем. Все записи ученикам запрещены. Техническая проверка правил описана в README.

## 4. Создайте аккаунт преподавателя

1. **Build → Authentication → Sign-in method**: убедитесь, что **Email/Password** включён.
2. **Users → Add user**: укажите свой email и надёжный пароль.
3. **Authentication → Settings → Authorized domains**: добавьте `localhost` для локального запуска и домен будущего сайта. Адрес указывается без `https://` и пути.
4. Войдите на сайте этими данными. Не передавайте пароль ученикам. Смена пароля доступна через управление аккаунтом в Firebase; публичной регистрации и кнопки сброса пароля в первой версии нет.

## 5. Проверьте защиту

В Firestore **Rules → Rules playground** проверяйте запросы с выключенной аутентификацией:

1. Чтение `vocabularySets/ID_НАБОРА` должно быть отклонено.
2. Запись в `vocabularySets/ID_НАБОРА` должна быть отклонена.
3. Запись в `publicPractices/ID_ССЫЛКИ` тоже должна быть отклонена.
4. Чтение существующего `publicPractices/ID_ССЫЛКИ` после публикации должно быть разрешено.

Для проверки запрета перечисления коллекций и доступа другого владельца запустите тесты эмулятора из README. Не меняйте защиту ради устранения ошибки входа: сначала проверьте аккаунт, конфигурацию и проект.

## 6. Проверьте ссылку ученика

1. Создайте набор минимум из четырёх слов, сохраните его.
2. **My library → Share → Publish & get link → Copy link**.
3. Откройте ссылку в режиме инкогнито. Вход не нужен; кабинета, email и кнопок редактирования быть не должно.
4. Пройдите все четыре раунда, сделайте одну ошибку, затем нажмите **Practise mistakes**.
5. В кабинете измените слово и сохраните. Заново открытая ссылка должна показать обновлённый набор.
6. Через меню `••• → Unpublish link` отключите ссылку. После обновления страницы ученик увидит сообщение о недоступном наборе.

## 7. Что не нужно менять без причины

- Не включайте открытый доступ к Firestore и не заменяйте правила на `allow read, write: if true`.
- Не добавляйте ключи администратора в код сайта.
- Не удаляйте проект, базу, аккаунт учителя или коллекции вручную.
- Не переименовывайте поля коллекций и не меняйте `schemaVersion` вручную.
- Не меняйте регион базы и не создавайте второй проект вместо существующего.
- Ученические ссылки публичны для тех, у кого они есть: не включайте личные сведения в слова и примеры.

Перед крупными изменениями скачивайте **My library → Export**. Для переноса выберите **Import**: он добавляет новые приватные копии. Существующие наборы и ссылки не перезаписываются.

Публикация сайта: выполните команды из раздела Deploy в README. Сборку и правила нужно публиковать в один и тот же Firebase-проект. После изменения конфигурации для опубликованного сайта нужна новая сборка.
